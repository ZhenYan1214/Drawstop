# Legal / Real-World Data Sources for Chainlink CRE Workflows, and the Track Record of Oracle-Based Real-World Products

Research date: 2026-10-14. Facts dated before 2025 are marked **[older]**. Every source was fetched or searched during this session. Where a fact came only from a secondary or third-party page, that is noted.

---

## Q1. Data sources: access terms, cost, API quality, and fit with CRE limits

### Takeaway
The data sources that fit CRE best are free, keyless or single-key JSON APIs that return small responses: GLEIF LEI, SEC EDGAR, UK Companies House, Taiwan 商工登記 Open API, CourtListener, OpenSanctions match API, and ESMA/Taiwan FSC registers if mirrored. Bulk lists such as the full OFAC SDN XML do not fit, because CRE caps each HTTP response at 250 KB. Two sources need special handling. Taiwan's 司法院 judgment API only serves between 00:00 and 06:00, and its rules require you to delete judgments that are later withdrawn, which clashes with writing them on-chain. UK Find Case Law requires a free Computational Analysis Licence for programmatic bulk processing.

### Cited Findings

**CRE platform limits (binding constraints for every source below)**
- CRE service quotas, last updated 2026-09-16: up to 15 HTTP requests per execution, 120 KB request size, **250 KB response size**, 10 s connection timeout, 10-minute cache age. Confidential HTTP also allows 15 calls, with 500 KB responses and a 90 s timeout. EVM read allows 15 calls per execution, a 5 KB payload and log queries over at most 100 blocks. EVM write allows a 50 KB report, 10M gas and up to 10 target chains. The fastest cron interval is 30 s. Secrets: 5 fetch calls per execution, 2 KB per secret, 100 secrets per owner. The quotas are marked "subject to change". — [Chainlink CRE Service Quotas](https://docs.chain.link/cre/service-quotas.md)
- Other per-workflow limits: 3 concurrent capability calls, 5-minute total execution time, 100 KB maximum workflow return size, and a 25 KB consensus observation size. — [Chainlink CRE Service Quotas](https://docs.chain.link/cre/service-quotas)

**Court records**
- **CourtListener (Free Law Project) REST API v4.** Authentication is by token, header `Authorization: Token <token>`. The docs page lists throttles of "50 requests per hour and 125 per day, plus 5 per minute" for authenticated users, with the most restrictive limit applying. That is far lower than the commonly cited 5,000/hour, so the figures may apply only to certain endpoints. Check the Usage API before building on them. There are Alert APIs with **webhook delivery** for search queries and followed cases, RECAP APIs for PACER data, and a "Pray and Pay" feature for requesting documents. RECAP Fetch counts against the rate limit. Rules: one account per project; weekly maintenance on Thursdays 21:00–23:59 PT; commercial partnership agreements for more access. — [CourtListener API v4 overview](https://wiki.free.law/c/courtlistener/help/api/rest/v4/overview)
- **PACER fees.** In 2026: $0.10 per page, capped at $3 per document, waived if a user's charges are $30 or less in a quarter. From **2027-01-01** a temporary increase takes the rate to $0.12 per page and the waiver threshold to $40 for five years. — [D. Nev. Bankruptcy announcement 2026](https://www.nvb.uscourts.gov/news-rss/announcements/2026/0626-fees/); [M.D. Tenn. notice](https://www.tnmb.uscourts.gov/news/temporary-pacer-fee-increase-effective-jan-1-2027); the $3 cap comes from [OpenClassActions explainer](https://openclassactions.com/blog/what-is-pacer-court-records-fees-explained.php) (secondary).
- **UK Find Case Law (The National Archives).** The Open Justice Licence allows free commercial reuse, including copying, publishing and combining judgments into products. It does **not** cover computational analysis, defined as "programmatic searching in bulk ... to identify, extract or enrich contents". That needs a separate licence, now called the Computational Analysis Licence. It is free, but you must state your purpose, and it is risk-assessed against the Five Safes framework and nine MoJ principles. Fully automated legal advice is treated as high risk. The licence template is dated 2024-10-28. Contact: caselawlicence@nationalarchives.gov.uk. — [Find Case Law licence application process](https://caselaw.nationalarchives.gov.uk/licence-application-process); [Permissions and Licensing](https://caselaw.nationalarchives.gov.uk/permissions-and-licensing); [Law Gazette](https://lawgazette.co.uk/news-focus/in-depth-national-archives-to-expand-judgment-publications-service/5120821.article)
- **Taiwan 司法院裁判書開放API** (spec version 114.08.22, i.e. 2025-08-22):
  - Authentication: log in with a 司法院資料開放平臺 account to get a token valid for 6 hours.
  - Two endpoints: a change list (異動清單), returning judgment IDs (jid) changed from 7 days before the call date, and judgment content (裁判書內容) by jid. RESTful JSON; PDF and attachment URLs are returned for download.
  - **The service only runs from 00:00 to 06:00 daily.**
  - If a jid later returns "no data", the integrator **must delete** its previously downloaded copy to protect privacy.
  - — [司法院 opendata spec file](https://opendata.judicial.gov.tw/api/Newses/42/file) (seen via search summary)

Qualified vLEI Issuers (QVIs) handle issuance, verification and revocation. — [vLEI EGF v4.0 credential framework PDF](https://www.gleif.org/organizational-identity/become-a-vlei-issuer-qvi/vlei-ecosystem-governance-framework/2026-03-25_vlei-egf-v4.0-qualified-vlei-issuer-identifier-governance-framework-and-vlei-credential-framework_v1.6_final.pdf); [QVI program manual v1.5](https://www.gleif.org/organizational-identity/become-a-vlei-issuer-qvi/required-documents/2026-03-16_vlei-egf-v4.0-vlei-issuer-qualification-agreement-appendix-2-vlei-issuer-qualification-program-manual_v1.5_final.pdf); [GLEIF QVI qualification process](https://www.gleif.org/en/vlei/the-lifecycle-of-a-vlei-issuer/gleif-qualification-of-vlei-issuers/qualification-process)
- **UK Companies House.**
  - REST API: **600 requests per 5 minutes** per key, with a 429 for the rest of the window once exceeded. Higher limits are available on request.
  - The limit is per API key. Using multiple keys for one application counts as circumvention, according to staff on the forum.
  - Streaming API: no server-side filters, back off on 429, resume from the last timepoint.
  - — [Developer guidelines](https://developer.company-information.service.gov.uk/developer-guidelines); [Streaming API guide](https://developer-specs.company-information.service.gov.uk/streaming-api/guides/overview); [CH forum](https://forum.companieshouse.gov.uk/t/api-rate-limiting-and-streaming-api-endpoints-clarification/5256)

Submissions endpoint: `https://data.sec.gov/submissions/CIK##########.json`. A bulk ZIP is republished nightly around 03:00 ET. — [SEC Accessing EDGAR Data](https://www.sec.gov/os/accessing-edgar-data); [EDGAR API documentation](https://www.sec.gov/edgar/sec-api-documentation)
- **Taiwan 經濟部商工登記 Open API** (data.gcis.nat.gov.tw):
  - You must submit a 使用告知信 (notice of use) and pass review before integrating. Other datasets on the platform download freely.
  - data.gov.tw lists the 商工 datasets under 政府資料開放授權條款第1版 (Open Government Data License v1), free of charge.
  - Swagger spec: `data.gcis.nat.gov.tw/resources/swagger/swagger.json`.
  - Queries cover: company basics by 統一編號 (status 公司現況, capital, responsible person, address, approval dates), directors and supervisors with shareholdings, and whether a 統編 is a company, branch or business.
  - JSON or XML. Some datasets update hourly.
  - — [data.gov.tw dataset 13863](https://data.gov.tw/dataset/13863); [data.gov.tw dataset 84876](https://data.gov.tw/dataset/84876)

**E-signature events**
- **DocuSign Connect.**
  - Sends an HTTP POST of JSON (SIM mode, restv2.1) on events such as `envelope-completed`.

  - Legacy XML was retired in May 2023. Retries are aggressive, so deduplicate.
  - — [DocuSign dev blog](https://www.docusign.com/blog/developers/event-notifications-using-json-sim-and-hmac); [Hookdeck guide (secondary)](https://hookdeck.com/webhooks/platforms/guide-to-docusign-webhooks-features-and-best-practices)

  - `event_hash` is HMAC-SHA256 of event_time + event_type, keyed with the API key.
  - — [Dropbox help](https://help.dropbox.com/integrations/the-difference-between-signature-request-signed-and-all-signed-callback-events); [Dropbox Sign dev docs](https://developers.hellosign.com/api/manual-reference-pages/glossary/callbacks-events)

### Inferences
- Because of the **250 KB response cap**, CRE cannot download the full OFAC SDN XML, which is tens of MB (my estimate; size not verified). It also cannot pull EU or UN consolidated XML lists. Sanctions checks should use a *match* endpoint that returns a small JSON verdict (OpenSanctions `/match`, or the Chainalysis API), or an off-chain pre-indexed mirror. A mirror reintroduces a trusted party, which weakens the decentralization story.
- **OpenSanctions CC BY-NC** fits a hackathon demo, but writing the matched data on-chain is arguably redistribution. The safer design writes only a boolean or a hash plus a list-version ID on-chain. A commercial deployment would need a paid API or a Reseller licence.
- **Taiwan's judgment API** fits poorly for on-chain storage. The 00:00–06:00 window can be handled with a CRE cron trigger in Asia/Taipei time. But the delete-on-withdrawal rule means you should never store judgment text or identifiable data on-chain. Store only commitments, e.g. a jid hash plus outcome flag, ideally revocable.
- **UK Find Case Law**: an automated covenant-monitoring workflow that searches judgments programmatically probably needs the free Computational Analysis Licence. Mention this in a submission to show legal awareness.
- The best-fit sources for a 17-day build are SEC EDGAR, GLEIF, Companies House, 商工登記 and CourtListener. All are free, return JSON, have small per-entity responses and are deterministic, which suits DON consensus because all nodes see the same answer.
- E-signature webhooks are push events. CRE has an HTTP trigger, but DocuSign and Dropbox Sign cannot sign requests in CRE's required format. A small relay that verifies the HMAC and forwards to CRE, or a CRE cron that polls the DocuSign envelope status API with Confidential HTTP holding the OAuth token, is likely needed. This needs checking against the CRE HTTP-trigger docs.

## Q2. Real deployments: what launched, what worked, what failed and why

### Takeaway
Oracle-based products have worked where the trigger is objective, public and parametric (flight delay, rainfall or yield index) and the payout is small and automatic: Etherisc FlightDelay, and the Lemonade Crypto Climate Coalition paying Kenyan farmers through M-Pesa. Bank-consortium trade-finance blockchains (we.trade, Marco Polo, Contour, TradeLens) all closed in 2022–2023. They failed on adoption, volume, governance and funding, not because of the oracle or the blockchain itself. "Smart legal contract" platforms such as OpenLaw and Clause/Accord pivoted or stayed niche. Decentralized courts have seen limited uptake: Aragon's court effort failed, and Kleros now runs pilots with real courts.

### Inferences
- **The pattern of success**: an objective, binary or numeric trigger from a neutral public source; small value per contract; a payout the data provider cannot easily dispute; and a regulated insurer or reinsurer behind the product (Hannover Re, Atlas). **The pattern of failure**: multi-party network effects that require competitors to join a shared platform, and triggers that need human judgment.
- **For a hackathon**, a workflow that is useful bilaterally (one lender plus one borrower, or one escrow) and needs no consortium avoids the we.trade/TradeLens trap.
- **The oracle problem in legal triggers**: court dockets and registries are authoritative, but their entries can be ambiguous. A "filed" petition is not the same as a judgment. Designs should map triggers to *events defined in the contract*, such as "a winding-up petition is filed against Borrower", and route ambiguous outcomes to human or Kleros review rather than an automatic remedy.
- I found no evidence that Clause/Accord plus Chainlink reached production scale. The "smart legal contract" market seems to have shifted to contract lifecycle management (CLM) tools without blockchain. This is an inference from the lack of post-2021 coverage.

### Gaps
- No published FlightDelay policy or payout totals, and no LCCC total payout figure.
- Current (2025–26) status of Etherisc FlightDelay, Arbol's Chainlink usage, and Clause.io.
- No information found on ACRE Africa plus Chainlink specifically. The Kenyan Chainlink crop-insurance deployment I found is the LCCC/Pula one.
- Kleros case volume statistics for 2025–26.

## Q3. Legal enforceability of smart contracts and smart legal contracts, and accepted "legal triggers"

### Takeaway
Major common-law systems already accommodate automated contract performance. US UETA §14 recognizes contracts formed by electronic agents, and Arizona (2017) and Tennessee (2018) have explicit smart-contract statutes. The England and Wales Law Commission concluded in 2021 that no statutory reform is needed. The UK Electronic Trade Documents Act 2023 is in force. MLETR has been enacted or followed in 13 jurisdictions, including Singapore (2021), the UK (2023), France (2024) and China (2025, bills of lading only). Taiwan amended its 電子簽章法 in April 2024, but there is no smart-contract-specific statute; enforceability rests on general contract law and party consent. In practice, the accepted approach is a hybrid: a natural-language contract that defines the trigger event and data source, with code performing the obligation.

### Cited Findings
- **UETA §14**: a contract may be formed by interaction of electronic agents "even if no individual was aware of or reviewed" their actions. Substantive law still governs the terms. 49 states plus DC and the USVI have adopted UETA. — [Illinois codification 815 ILCS 333/14](https://ilga.gov/legislation/ilcs/documents/081503330K14.htm); [Wikipedia UETA](https://en.wikipedia.org/wiki/Uniform_Electronic_Transactions_Act)
- **Arizona (2017)**: a contract may not be denied effect "solely because" it contains a smart contract term, and blockchain-secured signatures and records are valid. **Tennessee (2018)** defines a smart contract as an event-driven program on a distributed ledger and has the same non-discrimination rule. **Illinois** says smart contracts may be denied enforceability where a writing is required unless all parties can retain and reproduce them. — [Hunton state smart contract legislation](https://www.hunton.com/blockchain-legal-resource/2018/09/state-smart-contract-legislation/); [Proskauer on Illinois](https://www.proskauer.com/blog/illinois-embraces-smart-contracts-with-new-blockchain-legislation) **[older]**
- **England and Wales Law Commission, Smart legal contracts advice (25 November 2021)**: the current framework "is clearly able to facilitate and support" smart legal contracts. It identifies three forms: a natural-language contract with automated performance, a hybrid, and solely code. Further work is needed on deeds and private international law. It recommends express clauses that allocate code-performance risk and set out how the natural-language and coded parts relate. It builds on the UK Jurisdiction Taskforce's 2019 legal statement. — [Law Commission project page](https://www.lawcom.gov.uk/project/smart); [SCL](https://www.scl.org/12424-law-commission-concludes-that-the-laws-of-england-and-wales-can-accommodate-smart-legal-contracts/); [Baker McKenzie](https://blockchain.bakermckenzie.com/2021/12/02/smart-legal-contracts-are-enforceable-advises-uk-law-commission/) **[older]**
- **UK Electronic Trade Documents Act 2023**: in force from 2023-09-20. A document qualifies if a "reliable system" identifies it uniquely, protects it from unauthorized alteration and allows only one person to control it at a time. Reliability is assessed case by case. — [legislation.gov.uk](https://www.legislation.gov.uk/ukpga/2023/38/data.htm); [Clyde & Co](https://www.clydeco.com/en/insights/2023/08/electronic-trade-documents-act-etda-2023); [Hill Dickinson](https://www.hilldickinson.com/insights/articles/uks-electronic-trade-documents-act-now-force)
- **MLETR status (UNCITRAL official page; no update date shown)**: Bahrain 2018; Belize 2021; China 2025 (influenced; bills of lading only); France 2024; Kiribati 2021; Marshall Islands 2025 (influenced); Mauritius 2025 (bills of exchange only); Papua New Guinea 2022; Paraguay 2021; **Singapore 2021**; Timor-Leste 2024; ADGM (UAE) 2021; **UK 2023** (influenced). — [UNCITRAL MLETR status](https://uncitral.un.org/en/texts/ecommerce/modellaw/electronic_transferable_records/status). Hong Kong planned a 2026 legislative proposal. — [LetsDataScience (Dec 2025)](https://letsdatascience.com/news/hong-kong-advances-trade-digitalisation-with-mletr-410e56ac)
- **Taiwan 電子簽章法 amendment** (passed third reading 2024-04-30; first amendment since 2002):
  - Electronic documents and signatures cannot be denied effect *solely* because they are electronic.
  - Digital signatures backed by government-approved CA certificates are *presumed* to be the person's own signature or seal.
  - The other party must be given a chance to object to the electronic form; silence is presumed consent.
  - Agencies can only exclude the Act by statute.
  - Judicial-procedure exclusions are announced by 司法院 or 法務部.
  - After the amendment, banking and insurance had removed all their exclusions, and securities exclusions fell from 102 to 11.
  - — [Lee and Li newsletter](https://www.leeandli.com/TW/Newsletters/7256.htm); [工商時報 2024-09-26](https://www.ctee.com.tw/news/20240926702098-430301)

### Inferences
- A legally credible hackathon design is the **"hybrid smart legal contract"** in the Law Commission's terms. A natural-language clause names the trigger event, the authoritative data source (for example "the CourtListener/PACER docket for case X" or "Companies House status = 'liquidation'"), the oracle mechanism (CRE DON consensus) and the remedy. The code performs it. The clause should also include a dispute or override path and a statement that the data source prevails on error.
- **Triggers accepted in practice** (inferred from the deployments in Q2 and the trade-law regimes above): parametric indices (weather, flight status); documentary events such as signature completion, eBL transfer and filing on a public register; and status changes in authoritative registries. Triggers requiring legal judgment, such as "material breach", "reasonable efforts" or the merits of a court decision, are not reliably automatable and should only *flag* or *freeze*, not *finally transfer*.
- In Taiwan, smart-contract enforceability falls back on 民法 general principles plus 電子簽章法 consent. This is my inference; the sources did not address smart contracts directly.

### Gaps
- Singapore's ETA 2021 amendments: I relied on the UNCITRAL listing and did not fetch the Act's text.
- No 2025–26 English case law applying the ETDA "reliable system" test was found.
- No Taiwanese court decision or authoritative commentary on smart contracts (智慧合約) was retrieved.
- The E-SIGN Act §101(h) electronic-agent provision was not fetched.

## Q4. Candidate workflows (data source + legal condition + on-chain remedy) feasible in 17 days

### Takeaway
The strongest candidates combine free, small-response, deterministic registries (EDGAR, GLEIF, Companies House, 商工登記, CourtListener) with **bilateral** contract remedies such as escrow freeze or release, a loan covenant default flag, or an allowlist gate. They should write only booleans or hashes on-chain. Bulk sanctions lists and Taiwan judgments need design workarounds. Consortium-dependent trade-finance ideas should be avoided.

### Cited Findings
These candidates are built from the source facts cited in Q1–Q3, which are referenced inline. Feasibility notes are my assessments.

1. **Covenant monitor: borrower insolvency or status trigger (UK).** A CRE cron (for example daily) calls Companies House `/company/{n}` for company_status (active / liquidation / administration) plus Gazette insolvency notices. On a status change, it writes a "default event" to a loan or escrow contract, which freezes undrawn credit or accelerates. Data is free with 600 requests per 5 minutes, small JSON and deterministic ([CH guidelines](https://developer.company-information.service.gov.uk/developer-guidelines); [Gazette, third-party](https://apify.com/devon_gtme/uk-insolvency-notices-gazette)). **Feasibility: high.** About 2–4 HTTP calls per run.
2. **Covenant monitor: US litigation or bankruptcy docket trigger.** CourtListener search or docket alerts for a counterparty name or case number: new bankruptcy petition, or a docket entry matching "judgment" or "injunction". The workflow sets a flag or pauses an escrow, and human or Kleros review then confirms. Free API with webhook alerts, but tight throttles (verify) ([CourtListener v4](https://wiki.free.law/c/courtlistener/help/api/rest/v4/overview)). **Feasibility: medium-high.** Needs fuzzy-match handling; keep the remedy reversible.
3. **SEC filing-triggered covenant or reporting compliance.** A loan or token covenant says "Borrower must file 10-Q within N days of quarter end" or "8-K Item 1.03 (bankruptcy) triggers default". CRE polls `data.sec.gov/submissions/CIK.json`, which needs no key, at up to 10 requests per second ([SEC](https://www.sec.gov/os/accessing-edgar-data)). Remedy: a late-filing penalty step-up or a default flag. **Feasibility: very high**, with clean, deterministic JSON. The value story fits RWA private credit.
4. **Counterparty legal-entity verification (GLEIF LEI, plus vLEI as a stretch).** Before releasing funds or minting an RWA token, the workflow checks that the LEI is ISSUED (not LAPSED or RETIRED), the entity status is ACTIVE, and the parent relationship matches. It writes an attestation, LEI → address binding with expiry, to an on-chain registry ([GLEIF API](https://www.gleif.org/en/lei-data/gleif-api); CC0 per the [LOU template](https://www.gleif.org/about-lei/the-lifecycle-of-a-lei-issuer/gleif-accreditation-of-lei-issuers/required-documents/2023-07-19_ma-appendix-09b-terms-of-use-lou-template-1.3final.pdf)). **Feasibility: high for LEI.** vLEI cryptographic verification (KERI/ACDC) inside a CRE WASM workflow is **risky** in 17 days ([vLEI EGF 2026](https://www.gleif.org/organizational-identity/become-a-vlei-issuer-qvi/vlei-ecosystem-governance-framework/2026-03-25_vlei-egf-v4.0-qualified-vlei-issuer-identifier-governance-framework-and-vlei-credential-framework_v1.6_final.pdf)).
5. **Taiwan counterparty status check (商工登記).** Check 統編 → 公司現況 (核准設立 / 解散 / 廢止 / 破產), capital and responsible person. Use it as a precondition for a Taiwanese B2B escrow or for tokenized-receivable eligibility. Free under OGDL v1 after the notice-of-use review ([data.gov.tw](https://data.gov.tw/dataset/13863)). **Feasibility: high**, if API approval arrives in time. Apply immediately. A local-language angle may help differentiate with BLI judges.
6. **Sanctions-gated escrow or payment (OpenSanctions match plus Chainalysis oracle).** Before an escrow release, CRE calls OpenSanctions `/match` through Confidential HTTP, keeping the API key secret, for the counterparty's name, country and date of birth or registration number. It can also read the Chainalysis on-chain oracle for the wallet. It writes only a pass/fail plus a dataset version hash ([OpenSanctions licensing](https://www.opensanctions.org/licensing/); [Chainalysis](https://www.theblock.co/linked/137292/chainalysis-makes-new-crypto-sanctions-monitoring-tools-free-to-the-public)). **Feasibility: high technically.** Licensing: fine for non-commercial use under CC BY-NC, commercial use needs credits or a licence. Do *not* pull the full OFAC XML, because of the 250 KB cap ([CRE quotas](https://docs.chain.link/cre/service-quotas.md)).
7. **Regulated-counterparty gate (MiCA CASP or Taiwan VASP registration).** Before a token transfer or a liquidity partnership, check that the counterparty CASP or VASP is authorized in the ESMA register CSV or on the FSC 完成洗錢防制登記 list. Set an allowlist flag that expires and is re-checked by cron ([ESMA MiCA](https://esma.europa.eu/esmas-activities/digital-finance-and-innovation/markets-crypto-assets-regulation-mica); [工商時報 2026-09-29](https://ctee.com.tw/news/20260929701704-430301)). **Feasibility: medium.** The ESMA CSV may exceed 250 KB and the FSC list is an HTML page, so a small normalizing mirror may be needed, which weakens trustlessness. Timely, because 虛擬資產服務法 passed on 2026-06-30.
8. **E-signature-to-escrow ("signed, then funded").** A DocuSign `envelope-completed` or Dropbox Sign `signature_request_all_signed` event triggers CRE. CRE re-checks envelope status by API with the OAuth token in Confidential HTTP, then writes a document-hash commitment and releases a deposit or activates a payment stream ([DocuSign](https://www.docusign.com/blog/developers/event-notifications-using-json-sim-and-hmac); [Dropbox Sign](https://help.dropbox.com/integrations/the-difference-between-signature-request-signed-and-all-signed-callback-events)). **Feasibility: high.** Legally strong: signature completion is a documentary trigger, and the Taiwan 電子簽章法 presumption applies to certified digital signatures ([Lee and Li](https://www.leeandli.com/TW/Newsletters/7256.htm)). Less novel.
9. **Parametric clause inside a commercial contract (force majeure or delay LDs).** A supply or event contract's natural-language clause defines force majeure as rainfall over X mm or a typhoon warning at location Y, or a flight cancellation. CRE fetches Open-Meteo or a national weather service (for example Taiwan CWA open data, not researched) or FlightAware, then suspends liquidated damages or releases a refund ([FlightAware](https://flightaware.com/commercial/aeroapi/); [Open-Meteo, secondary](https://geekflare.com/guides/weather-api/)). **Feasibility: very high** and proven in practice (Q2), but **least novel**; prior art includes Etherisc and Arbol.
10. **Judgment-triggered escrow release (court outcome as condition).** An escrow holds funds pending a court case. When the docket shows final judgment or dismissal (CourtListener; Taiwan 司法院 change list for a known jid), CRE proposes a release and a challenge window allows override. Taiwan's API is only available 00:00–06:00, and withdrawn judgments must be deleted, so store only jid hashes ([司法院 spec](https://opendata.judicial.gov.tw/api/Newses/42/file)). **Feasibility: medium.** Parsing outcomes is ambiguous, so it needs a human or Kleros confirmation step ([Kleros/Mendoza](https://thedefiant.io/kleros-to-collaborate-with-supreme-court-of-mendoza)).
11. **Pay-per-check legal compliance API via x402.** Wrap candidates 3–7 as a paid compliance-check endpoint. An AI agent or dApp pays per call, CRE runs the checks and returns a signed on-chain attestation. **Feasibility: medium.** The x402 integration details were not researched here. The novelty is high, given the earlier note that no hackathon winner has done this.
12. **UK eBL / ETDA "reliable system" control-transfer attestation.** CRE watches a DCSA-standard eBL platform API for a transfer of control and triggers documentary-collection payment ([ETDA](https://www.legislation.gov.uk/ukpga/2023/38/data.htm); [DCSA](https://thedigitalship.com/news/maritime-software/dcsa-announces-plans-to-push-for-electronic-bills-of-lading/)). **Feasibility: low in 17 days.** eBL platform APIs (CargoX and others) are commercial and closed, and sandbox access is uncertain.

### Inferences
- **Best fit for value, novelty and feasibility**: a combined **"Covenant Sentinel"** for RWA private credit or escrow (candidates 1+3+4+6). One CRE cron workflow checks entity status (GLEIF / Companies House / 商工登記), filings (EDGAR), litigation or insolvency (CourtListener / Gazette) and sanctions (OpenSanctions), all within 15 HTTP calls. It writes a compact covenant-health bitmap plus evidence hashes to a loan contract, which applies graduated remedies: warn, freeze, then default only after a cure period. It is bilateral, so it needs no consortium, and it addresses the Q2 failure patterns.
- Keep on-chain data minimal (flags plus hashes). This respects the OpenSanctions NC licence, Taiwan's delete-on-withdrawal rule and the UK computational-licence scope, and fits the 50 KB report and 5 KB read payload caps.
- Any remedy based on an ambiguous legal source (dockets, judgments) should be **reversible or challengeable** (a timelock plus override). This matches the Law Commission's advice to allocate code-performance risk by express clause.

### Gaps
- x402 plus CRE integration specifics and existing examples were not researched here.
- Whether CRE's HTTP trigger can accept third-party webhooks (DocuSign HMAC) directly, without a relay.
- Taiwan CWA (中央氣象署) open-data API terms were not researched.
- Real demand validation, for example whether private-credit RWA issuers actually want automated covenant monitoring, was not researched.
